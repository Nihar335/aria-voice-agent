Aria: the system architecture of an AI sales voice agent

Aria answers sales calls for Indian businesses in English, Hindi, Hinglish, Kannada and Telugu. It answers only from approved company documents, qualifies the lead, books a demo into the CRM and hands a summary to the sales team. 1 · SYSTEM ARCHITECTURE

What runs today, and how the parts talk

One Python backend (FastAPI) serves the web page and the API. Each customer turn runs through an eight-layer pipeline. Every outside dependency sits behind one module, so it can be swapped, and every one has a fallback, so a live call never goes silent.

Customer call path Staff path (signed in, role-checked) Reads and writes to storage Calls to cloud APIs

One gateway per dependency

llm.py, stt.py, tts.py and crm.py each hide one outside service. Moving from SQLite to Fortivex CRM, or from Groq to Vertex AI, changes one file.

A fallback at every layer

Groq ⇄ Gemini across five models; embeddings → keyword search; Whisper ⇄ Gemini STT → browser recognizer; Gemini voice → edge-tts → browser voice; all LLMs down → handoff to a human.

The LLM suggests, code decides

Tools validate every argument (a demo slot must really be free), the lead score is a formula, and the output guardrails are code, so a clever prompt cannot talk them out of a rule.

2 · END-TO-END BUSINESS WORKFLOW

A clinic owner calls in and leaves with a booked demo

Ravi runs a dental clinic in Jayanagar and misses calls after 7 pm. He calls Aria at 9 pm. This is the exact path through the code, from his first word to the sales team's dashboard. It is the same script used in the live demo.

  1. The call starts and Aria checks who is calling.
    A new session is opened. The phone number is looked up in the CRM; a returning caller's last summary is loaded as memory, so Aria can say "welcome back".
    POST /api/call/start → agent.py → crm.db
  2. Ravi speaks and the server writes it down. "Hi, I run a dental clinic in Jayanagar. We miss a lot of calls after 7 pm."
    The page records clean 16 kHz audio; Whisper transcribes English and Hindi, Gemini handles Telugu, Kannada and Hinglish, and either one covers for the other.
    call-core.js → POST /api/call/stt → stt.py → Groq / Gemini
  3. Input guardrails run first.
    Card, Aadhaar, PAN and OTP numbers are masked before anything is stored or sent to a model; prompt injection and abuse are caught by code.
    POST /api/call/turn → layers/guardrails.py
  4. Aria answers from the company's documents. "How much would this cost?"
    RAG finds the pricing section and its source; the router sends this FAQ to the fast model, and a repeat of the same question is served from the cache with no LLM call.
    rag.py → layers/router.py → layers/cache.py → llm.py
  5. Objection in Hinglish. "Thoda mehenga lag raha hai, discount milega?"
    The language is detected from what he said, the reply comes back in Hinglish, and the objection-handling notes from the knowledge base are used. No discount is invented: the output guardrail rejects any price not in the facts.
    analysis.py · knowledge_base/04_objections.md
  6. Booking with real tools. "Okay, book a demo tomorrow at 3."
    The router picks the strong model. The model calls check_availability, gets the free slots, then book_appointment with "2026-11-27 15:00". Code checks the slot is really free, saves it, and builds a Google Calendar link.
    pipeline step 6 → tools.py → crm.db (appointments)
  7. The reply is checked, spoken and traced.
    The output guardrail allows "your demo is booked" only because the tool really booked it. The reply goes to TTS and back to the page as audio. One trace records every step's time, tokens and cost.
    guardrails.check_output → tts.py → observability.db
  8. Scoring happens after he hears the reply.
    A background task updates sentiment and the BANT score (need, budget, authority, timeline). The admin cockpit shows it live; an upset caller raises an alert.
    BackgroundTasks → analysis.py → crm.db → GET /live
  9. The call ends and the sales team takes over.
    Aria writes the summary, objections and next steps. The lead, the score and the booked demo appear on the sales dashboard. Ravi gets a private link to his own call summary.
    POST /api/call/end → admin dashboard · my-calls.html
Business result: an after-hours call that would have been missed becomes a qualified lead with a booked demo, a CRM record and a summary for the sales rep, with no staff time spent. A typical turn takes 2-4 seconds with the natural voice.
3 · PROBLEM, IMPLEMENTATION, COMMERCIAL FEASIBILITY

Why it is worth building, and how it is built

Business problem

Missed calls are lost revenue

  • Indian SMBs (clinics, real estate, education, services) miss enquiries after hours, at peak times, or in a language the executive doesn't speak.
  • Calls that are answered get qualified inconsistently and rarely reach a CRM with notes.
  • A human executive covers office hours and one or two languages.
Technical implementation

Python, built from scratch

  • FastAPI backend, vanilla JS front end, no no-code tools.
  • 8-layer turn pipeline: guardrails, RAG, router, cache, versioned prompt, LLM with tools, output checks, traces.
  • Groq + Gemini models; Whisper and Gemini for STT; Gemini and edge-tts voices.
  • Google OAuth with five roles; tools also served over MCP.
  • 49 offline unit tests; 22 golden conversations scored by code and an LLM judge.
Commercial feasibility

Cheaper per call than a person

  • Cost ≈ ₹10 per 4-minute call; sample Growth plan ₹45,000 for 2,000 calls ≈ ₹22.5 per call → ~55% gross margin.
  • A human executive costs the client about ₹30 per call and works office hours only.
  • Fits the Fortivex ecosystem: an add-on for Fortivex CRM, and a vertical for Medivex AI (clinics) and Empowers Academy (admissions).

Sizing for scenario B

Live calls mostly wait on STT, LLM and TTS, so one 2-vCPU pod holds about 80-100 calls. 800 concurrent ÷ 100 = 8 pods; with 50% headroom that is about 12 voice-gateway pods and a similar number of agent pods, autoscaled on Kubernetes or Cloud Run by concurrent connections.

Targets

p95 from "customer stops talking" to "Aria starts talking" under 1.2 s, by streaming LLM tokens into TTS one sentence at a time. Availability 99.9%. The router and cache already cut LLM spend on FAQ turns.

Debugging a bad answer

  • Admin → Quality → open the turn's trace: facts used, route, model, prompt version, tools and their results, guard hits, time per step.
  • Server log tags show each fallback: [rag], [llm], [stt], [tts].
  • GET /api/health shows which providers are cooling down after a rate limit.
  • Each module runs alone: python rag.py, python llm.py, python agent.py for a text chat.

Safety net for live changes

  • python -m unittest discover tests: 49 tests, offline, about 3 seconds.
  • python evals/run.py: 22 golden conversations by category (grounding, guardrails, language, router, tools, voice). Last run: 22 of 22.
  • uvicorn main:app --reload reloads on every save.
  • If the mic or Wi-Fi fails, python agent.py runs the same agent in the terminal.
